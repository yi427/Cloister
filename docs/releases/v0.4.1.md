# Cloister 0.4.1

Release tag: `v0.4.1`. The matching base image is
`ghcr.io/yi427/cloister:0.4.1`.

This patch fixes Host MCP tool discovery in strict clients such as Claude Code
2.1.296. The bridge could connect successfully while Claude rejected
`tools/list` with `Invalid result for tools/list` because the result omitted
the required `ttlMs` and `cacheScope` fields.

The bridge now explicitly returns `ttlMs: 0` and `cacheScope: "private"` alongside
its five tools. Clients may fetch a fresh catalog when needed, and shared
intermediaries must not reuse it across authorization contexts. The existing
tool schemas, approval metadata, authentication, and execution policies are
unchanged.

The base tool versions are unchanged:

| Base tool | Version |
| --- | --- |
| Node.js | 24.19.0 |
| Rust | 1.97.1 |

## Upgrade

Update Cloister through the official Homebrew tap, then inspect and apply the
matching image update:

```sh
brew update
brew upgrade yi427/tap/cloister
cloister profile upgrade --dry-run
cloister profile upgrade
cloister check
```

Restart existing Agent sessions after upgrading. Their Host MCP bridges run
inside the CLI process that launched them; reconnecting an old session alone
does not replace that process.

Profile V7 and V8 remain supported. This patch does not change the schema or
broaden Host access. On-demand execution still grants the macOS user's authority,
and the workspace remains a live read-write Host bind mount.

## Validation

A regression test exercises authenticated HTTP tool discovery and requires both
cache fields and all five Host tools. The test reproduces the missing-field
failure before the fix. Local `make verify` passed all 230 tests and Clippy.
Checks against the exact published image and actual Claude client are recorded
in the [GitHub release](https://github.com/yi427/Cloister/releases/tag/v0.4.1).
