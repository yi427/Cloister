# Cloister 0.4.2

Release tag: `v0.4.2`. The matching base image is
`ghcr.io/yi427/cloister:0.4.2`.

This patch fixes routine Host Exec audit messages disrupting interactive Claude
and Codex terminals. Previously the bridge printed an audit summary to stderr
after every execution. The embedded bridge shares the terminal with the Agent,
so those messages could appear in its input area and interrupt screen updates.

Execution lifecycle metadata now stays in the owner-only JSONL audit file.
Command stdout and stderr remain available through MCP, and audit write failures
still produce an error diagnostic. Authentication, execution policies, tool
schemas, and audit-file contents are unchanged.

The base tool versions are unchanged:

| Base tool | Version |
| --- | --- |
| Node.js | 24.19.0 |
| Rust | 1.97.1 |

## Upgrade

Update Cloister through the official Homebrew tap, then inspect and apply the
matching image update:

```sh
brew update
brew upgrade yi427/tap/cloister
cloister profile upgrade --dry-run
cloister profile upgrade
cloister check
```

Restart existing Agent sessions after upgrading. Their Host MCP bridges run
inside the CLI process that launched them; reconnecting an old session alone
does not replace that process.

Profile V7 and V8 remain supported. This patch does not change the schema or
broaden Host access. On-demand execution still grants the macOS user's authority,
and the workspace remains a live read-write Host bind mount.

## Validation

A regression test launches the Claude and Codex CLI paths with a simulated
container and a real authenticated local HTTP MCP client. It checks successful
and nonzero command exits, verifies that no routine audit output reaches the
Agent terminal, and confirms command output and file-audit lifecycle records.
The test reproduces the terminal-output failure before the fix. Local
`make verify` passed all 231 tests and Clippy. Checks against the exact published
image are recorded in the
[GitHub release](https://github.com/yi427/Cloister/releases/tag/v0.4.2).
